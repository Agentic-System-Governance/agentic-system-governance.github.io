# 术语表

[返回首页](README.md)

| 术语 | 在本 Wiki 中的含义 |
|---|---|
| 工作 agent | 选择并执行具体任务方法的 agent，例如检索、写作和调用工具 |
| governance agent | 被授予一项或多项治理职责，并在相应权限内判断、协调或干预的 agent |
| 治理系统 | 共同承担治理的人、机构、程序和技术控制；范围大于一个治理 agent |
| 任务约定 | 将用户需求与系统能力、有效规则和授权条件对齐后，明确任务要求、分工、行动条件、完成依据、治理权限与决定方式的有效约定 |
| 治理规则 | 任务约定中需要在运行中检查的要求与条件，包括任务义务、行动权限、前提条件以及恢复和完成条件；可来自已有制度或有效决定，不限于程序代码 |
| 任务约定对齐（Mandate Alignment） | 通过交互协商确认交付条件与执行边界，将承诺落实为检查、控制和复核责任，并持续维护其有效性 |
| 交付条件 | 任务承诺的产物、验收要求及支持验收的证据 |
| 执行边界 | 获准操作、资源限制、委托范围和保留给有权主体的决定 |
| 授权 | 有权主体允许某个主体在特定范围与条件内行动；技术能力不自动产生授权 |
| 履行义务 | 接受职责后应当做的事，例如报告故障、返回证据或完成指定交付 |
| 执行故障 | 某个步骤或运行没有按预期工作，例如查询超时；未必涉及违规 |
| 停滞 | 在任务与资源条件下，没有可辨认的合理进展，例如重复同一失败动作 |
| 治理失效 | 被指派的治理职责在其声明条件下没有得到履行；不等同于任务失败 |
| 恢复 | 排除执行阻塞，使相应工作能够在允许条件下继续；恢复动作已执行不等于恢复条件已满足 |
| 故障处置（Fault Resolution） | 调查失败或不符合要求的执行，修正导致或维持问题的运行条件，并修复已受影响的状态 |
| 失败归因（Failure Attribution） | 用执行证据解释促成失败的条件、关键决定和影响传播路径；保留尚未证实的假设 |
| 运行修正（Operational Remediation） | 调整计划、调用、工具或运行条件，针对已诊断或疑似故障恢复合理执行 |
| 状态修复（State Restoration） | 修复故障已经影响的记忆、产物与外部资源，保留仍有效的变更并说明无法补救的影响 |
| 多智能体协调（Multi-Agent Coordination） | 在有效任务约定内组织 agent 与人类参与者的相互依赖工作，包括子任务分配、依赖管理和一致性维护 |
| 纠正 | 改变偏离要求的行为、结果或治理安排；应说明改的是哪个对象 |
| 升级处理 | 将问题交给具有所需权限、能力或责任的人或系统，并安排等待与接管 |
| 执行监督（Execution Oversight） | 通过风险监测、监督干预和结果核验，判断活动能否继续，以及实际效果是否支持继续或完成 |
| 核验（Verification） | 将当前状态、行动与结果的证据对应到适用规则，判断任务要求、权限或恢复与完成条件是否成立；贯穿运行过程 |
| 验收 | 根据事先确定的条件判断任务或交付物是否可以接受 |
| 外部效果 | 工具在业务系统中实际造成的变化，例如退款入账、采购下单或客户记录改变，而非仅发出请求 |
| 防重处理 | 在声明的业务标识和服务条件下，避免同一操作重复产生效果；不能默认所有工具都提供 |
| 交接 | 将任务、当前授权、待决事项和后续责任交给接收方；发出消息不等于已有人接手 |
| 共享权限 | 业务记录上授予其他主体的访问关系；是否随负责人修改而改变，需要按具体系统确认 |
| 待确认 | 当前证据不足以判断条件是否满足；需要补充依据，不能自动判为未满足或已满足 |
| 结果未知 | 实际效果尚待确认，不能当作行动未发生或已经失败 |
| 回滚 | 把可逆状态恢复到较早状态；不能默认撤销所有外部效果 |
| 补救 | 对已经造成的影响采取后续处理，例如更正或联系责任方；不一定消除原影响 |
| 责任归属（Responsibility Attribution） | 将实际行动连接到委托方、执行者、批准者和复核者，追溯各自的授权范围及承担的职责；不自动构成责任裁定 |
| 可审计性保障（Auditability Assurance） | 保障执行重建、责任归属和合规评估能够依据记录开展；证据完整性、留存和按权限获取支撑这三项工作 |
| 执行重建（Execution Reconstruction） | 从关联记录还原上下文、决定、工具行动和外部效果之间的过程，区分提议、发出、确认与实际发生 |
| 合规评估（Compliance Assessment） | 将实际轨迹中的行动和数据使用对应到当时适用的要求与授权，作出有证据支持的结论并保留未决事项 |
| 证据留存（Evidence Preservation） | 保存必要记录及其对象、时间、版本和依赖关系，是可审计性保障的支撑机制 |
| 可追溯性（Traceability） | 依据保留的证据重建关键经过及参与情况的能力；由关联证据支持，是可审计性保障所需的能力 |
| 执行框架 | 组织 agent 的循环、工具调用、状态和控制的运行层，主稿称 harness |
| 治理决定权限 | 治理判断、规则调整和接续决定由谁作出；区别于工作 agent 的任务自主性 |
| 授权内自主处理 | governance agent 在获授治理权限内自主调整、继续或中止任务；权限覆盖的规则变更无需等待人工决定 |
| 有人类介入的设置 | 人可以参与规则变更或给出新决定，系统需明确等待状态、响应安排与跟进责任 |
| 中止 | 根据当前条件停止任务的后续执行，并说明依据与未解决事项；不自动撤销先前动作或在途效果 |

英文保留在需要与综述对照的地方；具体操作语义以任务、服务能力与当前授权为准。
