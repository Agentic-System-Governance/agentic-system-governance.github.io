# 多智能体协调

[返回首页](../README.md)

**Multi-Agent Coordination 的职责，是在有效任务约定内组织 agent 与人类参与者之间相互依赖的工作，使分工、推进条件和共同产物持续相容。** 子任务分配明确谁执行、谁跟进；依赖管理判断什么工作已经具备推进条件；一致性维护检查各方采用的依据、状态与产物能否共同使用。各自完成任务，并不意味着系统已经能够交付。

沿用季度销售报告的例子：分析 agent 从获准数据源计算销售额变化，写作 agent 据此编写摘要和正文。任务约定已经明确，报告采用截至交付时最新已确认有效的数据，文字结论必须得到分析结果支持。两者能够交换产物及版本信息，governance agent 有权检查协作状态、安排更新并暂缓不满足条件的交付。

## 子任务分配（Sub-Task Allocation）

分工需要包含交接与后续跟进。分析 agent 负责提供数据版本、计算结果和必要的解释，发现适用数据更正时更新分析；写作 agent 负责在成稿中落实结果，并核对引用。governance agent 维护这些责任及交付条件，使分析结果送出后，后续更新仍有明确的承担者。

分析 agent 先给出“本季度销售额较上季度增长”，写作 agent 据此完成相关段落。交付前，数据源发布更正版；分析 agent 确认适用于本报告，重新计算后将结论修正为“销售额下降”。这并未改变任务目标或授权范围：分析 agent 提供更正依据，写作 agent 修订依赖旧结果的内容，governance agent 跟踪交接与未完成事项。

安排“谁通知谁”还不够。需要明确谁确认新结果可用、谁修订受影响内容，以及由什么证据确认交接完成。若任务需要重新分配，已发出的请求和待处理反馈也应有承接者，不能因原执行者退出就无人跟进。

## 依赖管理（Dependency Management）

更正后的分析已经可用，写作稿却仍依赖旧结论。governance agent 应据此将受影响的写作工作重新标为待更新，并暂缓最终交付；不依赖这次变化的背景介绍仍可保留和继续整理。

关键判断是哪些内容实际依赖旧分析。除了直接引用的增长数字，“需求正在扩大”这样的概括也可能由增长结论推导而来，但未逐句登记依赖关系。只替换数字或搜索“增长”未必覆盖这些推论；反过来，也不能把所有涉及销售的内容都判为失效。需要结合段落依据、分析过程与新旧结果的差异，确定修订范围及仍然有效的内容。

版本管理和依赖图可以自动标记已经登记的下游产物，消息系统可以传递更新。governance agent 要确保本次变化产生的语义依赖也被纳入，并把修订任务交给相应执行者。写作 agent 收到更新，只表示取得了输入，尚未满足重新交付的条件。

## 一致性维护（Consistency Maintenance）

写作 agent 按新分析修订后，需要检查摘要、正文和引用的数值是否采用相容的依据。把“增长”改成“下降”却保留基于增长作出的解释，仍不能支持交付；各方都声称使用最新版，也不能证明写作内容已经落实了更正。

一致性要求来自任务中的关系，不要求两个 agent 表达相同观点。分析结果支持销售额下降，写作可以提出有依据的解释或保留不确定性，但不能继续把未经支持的增长推论当作事实。核对时既要检查版本和数字，也要检查结论与证据之间的关系。

相关内容更新并得到核验后，可以解除这次协作调整对交付的限制，其他有效完成证据无需重复获取。固定流程能控制等待与版本切换，模型能辅助理解文字依赖；二者都需要可靠的来源关联、明确的跟进责任和对实际产物的检查，才能说明这次变化已被共同交付正确吸收。
