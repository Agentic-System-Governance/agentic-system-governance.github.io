# 任务约定对齐

[返回首页](../README.md)

**Mandate Alignment 的职责，是将用户意图转化为有授权依据、能够落实并持续维护的任务约定。** 约定包含两类承诺：交付条件说明要交付什么、如何验收及需要哪些证据；执行边界说明允许采取哪些行动、使用多少资源、委托哪些工作，以及哪些决定必须保留给有权主体。交互协商形成承诺，承诺落实把它们接到检查与控制上，持续维护使其在条件变化后仍然有效。

用户说“帮部门采购一批电脑”，还没有说明具体需求、可以动用的资源和完成条件。governance agent 应作为用户与 agentic system 之间的中介，主动了解双方条件，明确需要决定的歧义、取舍与授权，并明确谁有权作出各项决定。任务目标与可落实方式在这一过程中共同明确，用户无需先了解全部工具接口。

## 交互协商（Interactive Negotiation）

假设本例系统具备查询供应商、比较配置、下单、付款和跟踪交付的工具，工作 agent 可以承担采购执行。部门已有收货人负责核对实物并登记结果，物流工具本身无法确认箱内设备。这些能力与协作条件需要和本次需求一起考虑。

经对齐，任务要求明确为：为五位新同事采购五台用于日常文档和视频会议的电脑，符合部门已有配置标准，总费用含税和运费不超过 30000 元，周五前到货；本次包括数量、型号与外观核对，不包含系统安装。这些是本例约定的要求。

这里的判断不只是把一句话填进采购表。用户说的“周五前到货”和“新同事周五能用上”可能需要不同的交付条件；governance agent 要结合用途、安装能力和收货安排确认本次承接哪一种，并将仍需决定的取舍交给有权主体。不能由模型自行选一个解释，再把它当成用户已经接受的承诺。

工作安排随之明确：工作 agent 查询、选型、下单、付款并跟踪交付，已落实的收货人提供实物核对结果。governance agent 应确认已有收货安排适用于本次任务，并将核对结果纳入完成依据，不能仅凭物流签收判断整个任务完成。参与者、工具或观察手段尚未落实时，应明确哪些要求暂时无法承担。

交付要求也要与系统可控制的范围对应。工作 agent 可以根据供应商的预计到货信息选择方案，但无法保证运输必然准时。因此，任务约定还需明确预计延期时 governance agent 能够决定哪些调整，哪些决定在有人类介入的设置下由人作出。识别不确定性不意味着自行降低周五前到货的要求。

## 承诺落实（Commitment Operationalization）

具备付款工具不等于获得本次付款权限。governance agent 应将采购所需的对象、动作、数据与已有规则和有效授权对应起来：哪些供应商和收款路径可以使用，预算上限是多少，收货信息可以用于什么目的，以及哪些交易条件必须满足。

假设本例已获准通过指定供应商目录自主采购，预算批准和工具授权覆盖相应下单与付款。有效采购规则允许支付一笔订金，并要求卖方确认备货后才能支付余款；这些规则将用于执行中的具体交易。预算许可不会自动覆盖重复支付，能够读取人员资料也不意味着可以将全部资料交给供应商。已有有效依据可以直接采用，缺少的授权则需由有权主体补齐。

治理本身的权限也需要落实。在本例中，governance agent 可以核对订单与支付状态，并通过执行控制暂缓不满足条件的付款；它无权自行提高预算或改变交付要求。允许观察不意味着能够阻止行动，任务约定应与系统实际可用的控制方式对应。

明确后的任务约定汇集任务要求、工作分工、授权范围、行动条件与完成依据，并采用适用的关键记录保留和查阅要求。其中需要在运行中检查的要求和条件，统称为治理规则。Mandate Alignment 识别并落实已有规则，必要时取得新的有效决定，不自行创造组织政策或扩大授权；这些规则也不必全部表现为程序代码。

承诺还需要有实际落点：费用上限接到下单和付款检查，备货条件接到余款放行控制，实物要求交由已落实的收货人核对。固定程序可以执行金额与对象检查，但需要先确定检查什么、证据从哪里来，以及谁能处理无法自动判定的条件。仅把“必须符合要求”写进提示词，尚未建立这些检查与控制。

## 持续维护（Continuous Maintenance）

运行状态改变，不一定需要修改任务约定。付款从待确认变为成功，是在既有规则下更新事实；用户改变数量、预算授权调整或原有能力与协作条件失效，才需要重新对齐受到影响的要求与条件。governance agent 应采用有权主体作出的有效变更，并说明它影响哪些后续行动，保留原约定与更新依据供事后追溯。

更新不能停在约定文本里。受影响的工作 agent、付款检查和收货安排都应采用生效后的版本；已经下单或付款的部分则需要单独核对，不能假定改了数量或预算就自动改变已有订单。固定配置同步可以传播已知字段，仍需判断一次需求变化涉及哪些承诺、控制和在途行动。

任务约定还需明确治理决定权限与中止权限。获授权自主处理时，由 governance agent 在既定治理权限内处理变化，作出获授权的规则调整或执行决定；确认当前条件下无法继续时，可以中止任务并说明依据，无需等待人工接管。在有人类介入的设置下，可以由人修改规则或给出新决定，并明确决策请求、等待状态和跟进责任。约定变更应保留来源、版本与生效范围，不能通过覆盖旧约定抹去先前的行动与结果。
