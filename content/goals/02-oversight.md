# 执行监督

[返回首页](../README.md)

**Execution Oversight 的职责，是依据有效任务约定和运行证据，判断活动能否继续、需要什么限制，以及实际效果是否支持继续执行或确认完成。** 风险监测识别行动与执行轨迹中的风险和不确定性；监督干预把判断落实为放行、限制、暂停或升级；结果核验检查行动、干预和修复产生的效果。三项工作随证据变化反复发生。

沿用采购电脑的例子：系统已获准自主采购五台符合配置标准的电脑，总费用含税和运费不超过 30000 元，周五前到货。工作 agent 负责查询、下单、付款和跟踪交付，已落实的收货人负责实物核对；governance agent 可以查询交易并暂缓不满足条件的付款。需求、权限和必要能力已经明确。

## 风险监测（Risk Monitoring）

一家获准供应商报价 28000 元，要求先付 2000 元订金锁定货源，备货完成后再付 26000 元余款。已有授权允许这种安排，并要求卖方确认备货后才能结清货款。工作 agent 发起订金付款后遇到网络中断，未能取得结果；询问卖方时，对方回复“尚未收到订金”。

调用记录只能证明付款已发起，卖方回复也不能证明交易已经失败。当前应记为“本订单订金付款结果待确认”，继续查询原交易及到账情况。直接等待备货可能错过交付时间，另付一笔又可能重复支付。监测需要把不确定状态与这两种后果联系起来，决定优先取得什么证据。

这里要识别的不只是工具报错。供应商对“订金”“余款”和“已备货”的描述，需要对应到本订单的付款义务与交付条件；付款回执、卖方消息和订单状态也可能在不同时间更新。预算检查能发现超额，交易标识和幂等机制能防止同一请求重复执行，但不能单独判断一条新付款请求是否实质上重复履行了同一义务。模型可以帮助解释消息，仍需交易证据支持。

## 监督干预（Supervisory Intervention）

原交易结果未知时，governance agent 应通过付款控制暂缓新增订金支付，安排查询原交易；不受影响的交付信息核对可以继续。确认原交易失败后，才可在原授权内重新发起；确认到账后，则转入等待备货。这种干预无需先等常规重试失败，关键是下一次行动是否会扩大不确定后果。

准备支付余款时，应核对当前订单、收款对象、金额和备货完成的依据。“订金已收到”只支持收款状态，“准备安排备货”也尚未满足已经备货的条件。governance agent 需要将消息的含义对应到有效规则，再由可执行的控制决定放行或继续等待；不能仅凭金额仍在预算内就放行，也不能只向工作 agent 提醒一句后假定付款已被拦住。

已有授权覆盖且条件满足时，工作 agent 可以自主继续。等待将影响周五交付时，governance agent 应在获授权限内决定下一步；需要改变预算或交付承诺的，则由有权主体作出新决定。授权内自主处理不赋予额外权限，有人类介入时也应说明待决事项和等待期间的安排。

## 结果核验（Outcome Verification）

发出暂缓指令后，还要确认受控付款路径确实暂停；若请求已经发出，应继续查询它的实际效果。指令成功返回不能证明在途付款已取消，之后一次查询成功也不能自动证明此前没有重复支付。

确认订金到账，只支持这笔付款已经完成；确认备货，才支持相应的余款条件；全部付款成功，仍不能证明五台电脑已经按要求交付。最终核验应将订单、交易与收货证据对应起来，检查数量、配置、费用和到货时间。缺少实物核对结果时保持待确认，不用物流签收替代约定的验收。

核验也覆盖干预或修复后的状态。已有有效证据可以复用，但应确认它仍对应当前订单与产物。困难在于不同证据分别能支持哪一个结论、改变后的状态是否使旧结论失效；既不能让模型的一句“已完成”替代外部事实，也不能只因几个状态字段都显示成功就接受整体完成声明。
