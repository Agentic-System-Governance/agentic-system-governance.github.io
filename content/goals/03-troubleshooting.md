# 故障处置

[返回首页](../README.md)

**Fault Resolution 的职责，是调查执行失败或不符合要求的原因，修正导致问题的执行方法与运行条件，并修复已经受到影响的状态。** 它既处理任务无法推进，也处理工具报告成功却留下错误产物的情况。失败归因、运行修正与状态修复可以反复配合，不必先耗尽重试才开始处置。

以文档转换任务为例。假设用户要求将一份季度报告转换为 PDF，并据此生成摘要；内容必须完整，比较结论必须符合原文的统计口径。工作 agent 已获准使用转换服务、保存文件和编写摘要；governance agent 可以检查转换过程、暂缓交付，并安排获授权的修正。

## 失败归因（Failure Attribution）

转换服务返回成功，PDF 可打开，表中数字也与原文一致。但交付检查发现，原文中“统计口径已变更，两个季度不能直接比较”的说明没有出现在 PDF 中，摘要已据表中数字写出增长结论。现在需要查明说明在哪一步丢失，以及哪些后续内容依赖了这份不完整产物。

governance agent 调取同一版本的源文档、送入转换服务的中间文件与生成结果，发现该说明位于文本框中，预处理产生的中间文件已不包含它。对照保留文本框的输入进行隔离试转后，说明能够正常保留。这支持将问题定位到预处理环节；仅凭最终 PDF 缺字，无法区分源文件版本、预处理和转换服务本身的问题。

归因还需追踪影响：摘要使用了缺少口径说明的 PDF，因此增长结论需要重审。数字一致和工具成功回执都不足以排除内容损失；指出哪个工具参与过，也没有说明故障如何产生和传播。现有证据未覆盖的转换环节，应保留为待查范围。

## 运行修正（Operational Remediation）

本例中，重复提交同一中间文件仍会丢失说明。governance agent 安排工作 agent 修正预处理方式，保留与正文相关的文本框，再用完整输入重新转换。改动限定在获准的文档处理范围内，先检查受影响内容，再确认没有损坏其他段落、表格和版面。

修正需要对应已识别的问题和检验条件。本次应确认口径说明完整保留，并能与对应表格一起阅读；生成了一个新 PDF 只能证明产生了文件。若现有工具无法满足要求，应按既定权限选择其他处理方式，或中止并说明未完成内容，不能把“内容完整”悄悄降为“主要数字正确”。

固定的格式支持检查可以拦住已知缺陷，模型可以帮助识别说明与表格的语义关系。困难在于依据本次材料和转换记录确定丢失位置、选择有效改动，并用结果验证判断；只让模型再生成一次，或对所有失败统一重试，都不能完成这些工作。

## 状态修复（State Restoration）

转换方法修好后，交付目录中的旧 PDF 和已写出的摘要仍然有问题。governance agent 应根据产物版本与使用记录确定修复范围：以核验后的 PDF 替换待交付版本，安排重新审阅摘要中的比较结论，并保留仍有独立依据的内容。

本例中，摘要应说明两个季度口径不同，不能据现有数字直接判断增长；不依赖这项比较的业务介绍可以保留。若故障发现后已有有效修改，也应一并保留，不能简单回退整个目录而覆盖后续工作。文件回滚与依赖记录能够支持修复，但哪些段落实际依赖错误依据，仍需结合内容判断。

修复完成的依据，是待交付产物已采用有效版本，受影响结论已得到处理，且没有遗留仍被引用的错误副本。若有无法确认的外部副本，应明确其状态；本地替换成功不能证明所有后果都已消除。
